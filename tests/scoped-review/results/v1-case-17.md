Signal Desk is close to ready. The supplied desktop and mobile views show a readable queue, working filter feedback and a reachable reply preview. The main opportunity is to make the visual priority match the daily job of inspecting requests.

This is a production-close operations page. Staff are likely scanning between other tasks; ambiguity costs attention and can delay the next handoff. The bordered panels, quiet background and explicit green/amber status words give the page calm competence. Keep that direction, including the distinct elevation reserved for floating help.

**Give request work the strongest action signal.** The dark green “Export all requests” button carries more visual weight than either “Open request” action. On mobile it also occupies its own toolbar row, becoming a conspicuous stop before the owner and queue. That draws attention toward taking data away from the page while the stated job starts with inspection and waiting work. Unless exporting is the dominant operational task, give it the existing neutral button treatment. Keep the row actions explicit; their repeated wording is useful recognition, particularly for occasional users.

**Clarify the preview’s relationship to the filtered queue.** In the waiting capture, the queue correctly contains only Loading dock schedule, but the preview below still shows North wing access as “Ready for review.” The source confirms that preview is fixed to that request rather than following the filter or the opened request (`case-17.html:1`). Both names remain visible, so this is not evidence of a wrong reply being sent. It does create a context switch for someone concentrating on waiting work. If this is intentionally a separate preview, label that relationship, for example “Reply preview · North wing access,” and state that filtering does not change it. If it should follow request inspection, make that association explicit before polishing the panel further.

**Preserve the mobile and interaction strengths.** The table wraps names and actions without widening the document: the measurements report a 390px document at a 390px viewport. The lower capture shows the preview button fully reachable after scrolling, approximately 130 × 44px. The waiting measurement confirms that the first row is hidden and the owner remains visible. Source provides pressed filter states, shared filtering for the shortcut, a status announcement region, visible focus styling, named native dialogs with close buttons, and help that returns focus to the queue control. These are substantive reasons for confidence, rather than missing-state findings.

Typography supports scanning: system-ui, three declared sizes (16, 18 and 28px), normal/600/700 weights, and distinct body, muted, status and action text treatments. The title establishes entry, headings group the work, and short copy keeps reading manageable. There is no demonstrated need for another typeface or a broader visual redesign.

Prioritize action weight, then preview context. Those changes would help staff stay oriented while preserving the current product.
